## What ScholrNet Is

ScholrNet is a free academic networking and opportunity-discovery platform for school students in India. Its core mechanic: a student builds a single profile listing achievements (awards, projects, certifications, internships), and their school (via a counselor or teacher account) verifies those achievements with one click. The verified profile becomes a "trust portfolio" — a shareable link a student can send with college applications, scholarship forms, internship resumes, or competition entries instead of re-explaining and re-proving their history each time.

Alongside verification, ScholrNet runs an opportunity feed matching students to internships, scholarships, hackathons, competitions, and research opportunities, plus a lightweight social layer: connecting with classmates, teachers, and mentors, joining school clubs, and a public timeline for sharing achievements and opportunities.

## Security Architecture

### CSP (Content-Security-Policy)
Set in `app.py` `add_security_headers` after_request handler:
- `default-src 'self'`
- `script-src 'self' 'nonce-{nonce}'` — no `unsafe-inline`
- `style-src 'self' 'unsafe-inline'` — needed for dynamic theme colors
- `img-src 'self' data: blob: https:`
- `connect-src 'self' https://*.googleapis.com wss://*.firebaseio.com https://*.supabase.co`
- Per-request nonce generated via `secrets.token_hex(16)` in `set_csp_nonce` before_request

### CSRF Protection
Applied in `csrf_protect` before_request for all mutating methods (POST/PUT/PATCH/DELETE):
- Checks Origin or Referer header against allowed hosts (scholrnet.in, localhost, *.vercel.app)
- Returns 403 if neither header matches

### Session Security
- Flask session with PERMANENT_SESSION_LIFETIME
- Idle timeout: 30min via `check_idle_timeout` before_request (sliding window)
- Session invalidation: `session_version` column on User, password change/logout-all bumps version
- `get_id()` returns `"{id}:{session_version}"` — user_loader validates version

### Authentication
- Passwords hashed with bcrypt (Flask-Bcrypt)
- Login lockout: 5 failed attempts → 15min lockout (checked in auth.py login route)
- OTP comparisons use `hmac.compare_digest` (timing-safe)
- Firebase OAuth tokens validated server-side
- TOTP 2FA for optional extra layer

### Rate Limiting
- Auth endpoints: 3-30 per 15 minutes depending on sensitivity
- Org endpoints: 3-10 per 15 minutes
- Generic API: 5-60 per minute
- Default: 1000/day, 200/hour (from extensions.py)

### Admin Authorization
- `@super_admin_required` decorator on admin endpoints
- Inline `current_user.role != 'super_admin'` checks
- Role-based access in organization management (only principal/director/hr_admin can manage)

## Organization Onboarding Flow

```
Registration Page (/register-school, /register-institution, /register-company)
  │
  ▼ User submits form
POST /api/organization/register
  ├── Free email check → blocked with 400
  ├── Duplicate check (email + status) → 409 if exists
  ├── Risk assessment (domain match, free email check)
  └── Returns reg_id, sends OTP via email
  │
  ▼ User enters OTP
GET /verify-org-otp?reg_id=X
POST /api/organization/verify-otp
  ├── Validates OTP (timing-safe, 5/15min rate limit)
  ├── Creates Organization row (pending_approval)
  ├── Stores org_id back on OrganizationRegistration
  └── Redirects to /registration-pending
  │
  ▼ Admin reviews in Admin Panel
GET /api/admin/pending-organizations
POST /api/admin/organization/<id>/approve
  ├── Updates org status → 'approved', is_verified → True
  ├── Generates 48h invite_token, stores on OrganizationRegistration
  └── Sends activation email with link
  │
  ▼ User clicks email link
GET /activate-organization?token=XXX
POST /api/organization/activate
  ├── Validates token (not used, not expired)
  ├── Creates User + OrganizationMember (principal/director/hr_admin role)
  ├── Sets verified_school_id for school type
  ├── Sets org status → 'active'
  └── User can now log in
```

## Key Design Decisions

1. **Unified Organization model** with type enum (school/institution/company) instead of separate models — allows future types (NGOs, scholarship providers, training centers) without schema changes.

2. **Manual admin approval mandatory** — email verification alone never activates an organization. Admin must explicitly approve via admin panel.

3. **Invite token activation** — no passwords generated or emailed. Applicant clicks 48h link, sets own password.

4. **Two parallel school systems** exist — the legacy `School` model and the new `Organization` model (type=school). The `verified_school_id` bridge on `User` is set during new-flow activation. Future migration may deprecate `School`.

5. **Schools lazy-loaded via JS API** — not rendered in context processor. Reduces initial page weight.

6. **Landing page uses real DB data only** — never fake numbers, testimonials, or success stories.

7. **Purple primary color** (#6C3BF5) differentiates from competitors (LinkedIn=blue, Internshala=green, Unstop=blue).

8. **No password confirmation** on register — reduced friction tradeoff.

9. **Email verification not enforced** — users can explore before verifying (reduced friction).
